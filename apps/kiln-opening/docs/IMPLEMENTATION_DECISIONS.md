# IMPLEMENTATION_DECISIONS.md — V1.6.2

The [V1.6.2 Player Rulebook](./KILN_OPENING_v1.6.2_EN_SOURCE.md) governs mechanics. The [audit](./RULEBOOK_AUDIT_V1.6.2.md) records the owner's revisions (the latest, revision 5 of 2026-10-28, is changes 36–42), amendments and rulings (A1, superseded by change 27; A2; R1–R32, B1–B3; R3, R6, R9 and R19 are obsolete, R14 superseded, R20 changed by revision 5's free-action windows and owner ruling R26; R26–R30 of 2026-10-30 are the owner's confirmation of revision 5's interpretations I1–I5 and provisional default P6, and R31–R32 of 2026-10-31 answer its last two questions), editorial corrections, interpretations, provisional defaults, open questions and digital decisions. The [engine design](./ENGINE_V1.6.1_DESIGN.md), as amended by the [V1.6.2 delta](./ENGINE_V1.6.2_DELTA.md), is the implementation contract. This document lists how the online game represents those rules; where it summarises a ruling, the audit is authoritative.

## Versions and identifiers

- Rules `1.6.2`, state schema 10, `RULES_BEHAVIOUR_REVISION` 33. A room stores `r33-<content digest>`; a room from before owner revision 5 (schema 9, `r32-`), from before owner revision 4 (schema 8, `r31-`), from before owner revision 3 (schema 7, `r30-`), a V1.6.1 room (schema 6, `r29-`) or a V1.4 room (schema 5, revision ≤ 28) is rejected, never migrated (DIG).
- Stable IDs: Orders S01–S08 and O01–O48 (owner revision 2 rebuilt the Starting deck under S01–S08; S09–S16 are retired); Techs T01, T05, T10–T25 (retired T02–T04, T06–T09 and ST01–ST04 are never reused); Kilns RU, GU, GE, DI, JU; Contribution cards `BANK`, `TEND`, `STOKE`, `FUEL_LEDGER_BANK`, `FUEL_LEDGER_STOKE`; locations `materials_yard`, `commission_market`, `guild_hall`, `canal_wharf`, `magistrates_hall`, `form_decorate`, `glaze_load`; Shared Kiln spaces `high_1…3`, `middle_1…3`, `low_1…2`.
- Content values come only from `data/*.json` through `src/game/content.ts`. Game state is plain JSON and must survive Postgres `jsonb`'s key reordering: no rule depends on the key order of a `Record`.

## Engine boundaries

- The engine is pure and deterministic. All randomness goes through the seeded `RandomSource` (deck shuffles, the Kiln Die, the Main discard reshuffled into a new deck when a card is needed); the service stores the RNG state with every revision. A Select uses no randomness: its unreserved looked cards are discarded in look order (owner ruling R25).
- Validation sees only the actor's view (public projection + own private data). The UI, the computer player and the server call the same validators, so nothing offered to a client can be rejected for a reason it could not see.
- Every secret is structurally separate: server-only state under `GameState.hidden`, unrevealed Contributions in `PrivateFiringState`, private event payloads under `secret`. The public projection drops all three by construction.
- Timing windows mirror Appendix D one-to-one. A window opens only when someone has a decision; otherwise it resolves inside the command that reaches it. Every window has an always-legal exit.

## Setup and rounds

- Setup deals each player 2 Starting Orders secretly from the 8-card Starting deck (a 4-player game deals all 8; otherwise the rest go to the box), reveals 6 Main Orders off the Main deck (no reshuffle: nothing Main is dealt) and 2 Techs per discipline, then picks the First Player at random. Every seat starts with 2 Clay, 3 Wood and 3 Coins (no seat Coin, change 35). Then, in reverse turn order, one `SELECT_KILN { kilnId, mainOrder }` per player takes an available Kiln (all five, R1) and 1 face-up Main Order by display position in one turn (change 32, R23); the take is public (`ORDER_RESERVED` via `setup`) and the display is refilled to 6 at once, sliding left as L405 refills (INT Setup choice).
- The server rolls the Kiln Die publicly at the start of every round, Round 1 included (INT). The rotation in Rounds 2–5 discards the 2 leftmost Main Orders face down, slides and refills (B1 for an empty supply; every refill compacts and fills all empty positions as cards allow, provisional default P2).
- Setter's Mark placement is optional and asked at the start of the Work Phase (INT).

## Work Phase

- One worker action per Work turn; there is no pass. Canal Wharf is always legal; its Shifu gains 4 Coins and then takes the top Main Order unseen (B1: no card when the deck and the discard are both empty).
- **Free actions** (change 36, rev. 5 L168–176): `SELL_FLAWED` (a Finished Flawed ceramic for 2 Coins, its Vessel card back to the supply), `COMPLETE_ORDER` (a held Order, by the usual procedure) and `USE_IMPERIAL_PRIORITY`, any number in any order, only in the actor's own free-action window (`freeActionWindowOf`): the before-action and after-action steps of their Work turn and their Order Phase turn. They are refused during a worker action (`WORKER_ACTION_IN_PROGRESS`: a Select, the Guild Hall inspection; also during the Colour Samples swap's own Select, where the message names that Select, since the swap is no worker action), on another player's turn (`NOT_YOUR_DECISION`), and in Setup, the Setter's Mark window, every firing step and the Cleanup trim (`WRONG_PHASE`; owner ruling R26). `ORDER_COMPLETED`, `CERAMIC_SOLD` and `IMPERIAL_PRIORITY_USED` carry the `window`. Rewards gained before the placement count for it (a completion's Coins, Crowns and milestones). A ceramic loaded this round is not Finished until its firing finishes, so it can be neither delivered nor sold before then. A held Order may be completed as soon as it is held, the turn that reserved it included (after the reserving worker action, or after a swap's Select in either window; owner ruling R31).
- The before/after-action window offers the free actions and the Colour Samples swap (a Work-turn ability, not a free action, refused in the Order Phase) in any order (INT). The before-action window always opens. The after-action window opens, and after each action in it stays open, on public facts only (owner ruling R27): the swap usable, Imperial Priority usable, a Finished Flawed ceramic to sell, or at least 1 held Order and 1 Finished ceramic that is not Flawed; so its opening reveals nothing about the hand. When none holds, the turn ends by itself; `END_TURN` ends it at any time. A face-up reservation's display refill is deferred to the end of that turn, after the window (INT), so an Order reserved by the worker action may be completed in the same turn (owner ruling R31).
- Select N (change 25): every Select is one private look of the top N Main Orders (as many as remain, R16) followed by one `SELECT_CHOOSE`, whose picks are looked cards (secret) or face-up Orders (public; the position stays empty until the turn ends, then the display refills). The looked cards not reserved are discarded face down to the Main Order discard, in look order (owner ruling R25, which reversed change 24's deck bottom and made R19 obsolete); which they are is private to the looker (B3, `LOOKED_ORDERS_DISCARDED.secret`), the discard count public. When the deck is empty and a card is needed, the discard is shuffled into a new deck (L525): at the start of a look (never to complete one), at the Canal Wharf Shifu's draw and at a display refill. The step carries `select: { n, maxReservations, fromDisplay, lookedCount }`.
- Commission Market: the placement always opens the Select (Select 2 for the Apprentice effect, Select 3 for the Shifu effect, Senior Apprentice included); `SELECT_CHOOSE` reserves exactly 1 (Apprentice) or 1–2 (Shifu) in any mix. No resource is gained.
- Colour Samples: when acquired, a Select 3 with 1 mandatory reservation (R4) whenever an Order can be reserved. Its once-per-round swap (`USE_COLOUR_SAMPLES_SWAP`, then `SELECT_CHOOSE`) discards the held Order first (R17: a Main Order face down to the discard, a Starting Order to the box), then Selects 3. It can be used only if that Select could reserve an Order: a card to look at (counting the discarded Order, R17) or a face-up Order (B1).
- Guild Hall: the Apprentice buys 1 face-up Tech at printed cost. The Shifu's inspection is private; the Shifu then takes 1 or 2 Techs from different disciplines at printed cost, one `GUILD_TAKE` each, and `GUILD_FINISH` puts the untaken inspected Techs on the bottom in a private chosen order (B2). A taken Tech's position stays empty until the taker's turn ends; then every discipline refills to 2.
- Optional Tech and Kiln abilities may be declined without spending a once-per-round use (R4). Kiln Tending resolves automatically on the first qualifying Glaze & Load each round, and Canal Barge on the first Order its owner completes each round, in whichever free-action window (INT; owner ruling R30). Ru, Guan and Tribute Ware stay optional (R30); like Canal Barge they are once per round across every completion window of the round, Work turns and Order Phase alike (rev. 5 L176). Protective Saggars' floor and Fuel Ledger's free Bank and Stoke are always on.
- Materials Yard: the Apprentice gains 4 and the Shifu (Senior Apprentice included) 8 Clay/Wood in any split (change 34).
- Form & Decorate: each vessel costs its Shape's Clay + 2 Coins, whatever its Decoration (change 30). The Shifu's −1 Coin when forming 2 and Decorator's Kit's −1 Coin on any vessel (change 37) are separate reductions and may apply to the same vessel, whose 2 Coins become 0 (L658); placement legality counts them (L204). Ding's extra vessel costs 1 Clay + 2 Coins with any Decoration (change 40); it does not count against the action's vessel limit, nor toward the Shifu's "If you form 2" (owner ruling R29), and the engine keeps the reductions on the action's ordinary vessels, which gives the same totals (R29).
- Glaze & Load: a Glaze & Load action with at least one load into the Shared Kiln pays 1 Wood once, whatever its loads (changes 34–35, R24); an action loading only into the Imperial Kiln, and Imperial Priority, pay none. Placement is legal with a Shaped vessel and your own empty Imperial Kiln, or 1 Wood and a Shared destination (R5 as changed). Kiln Tending's Wood comes after the action and never pays its fuel (INT). There is no player Heat marker (changes 28, 31): the Shifu just loads up to 2.
- Kiln Master: its once-per-round +1/−1 marker is chosen with the load it goes on (`LoadSpec.kilnMaster`, `USE_IMPERIAL_PRIORITY.kilnMaster`), at any loading, into either kiln (R22); it is public, counts in Actual Heat, stays for a Second Firing recalculation and returns when the firing finishes. The tile has one marker: while it is on an Imperial ceramic loaded in the Order Phase, which waits for the next round's firing, Kiln Master cannot place it (`TECH_MARKER_IN_KILN`, owner ruling R32).
- **"End the turn afterwards"** (owner UI decision D21; `ENGINE_V1.6.2_DELTA.md` §16.24). An optional `endTurn` on the worker-action commands (the seven placements `PLACE_MATERIALS_YARD`, `PLACE_FORM_DECORATE`, `PLACE_GLAZE_LOAD`, `PLACE_COMMISSION_MARKET`, `PLACE_GUILD_HALL`, `PLACE_CANAL_WHARF` and `PLACE_MAGISTRATES_HALL`, but not `PLACE_SETTERS_MARK`; `SELECT_CHOOSE`, `GUILD_TAKE`, `GUILD_FINISH`) and the free actions lets the client end a Work turn or an Order Phase turn in the same command as its last confirm; absent, every command behaves as before, and the computer players never send it. A worker action whose commands asked for it ends the turn when it finishes (`completeWorkerAction`) instead of opening the after-action window; a request made before the action finishes is remembered on the public `work_turn.endTurnAfterAction` and replaced by a later command of the same action that carries the field. After the worker action, or in the Order Phase, a free action (or the swap's Select) with `true` ends the turn after it, as `END_TURN` / `END_ORDER_TURN` would; before the worker action `true` is `WORKER_ACTION_REQUIRED` and `false` is ignored. Events and state equal the two-command path's; `WORK_TURN_ENDED.automatic` is false exactly when an after-action window that would have opened on public facts (R27) was skipped. The field is public and reveals nothing about the hand; `endTurnOptions` tells the UI where it is accepted, from public facts only.
- Imperial Priority is a free action (rev. 5 L174, L314), so it may also be spent in the Order Phase turn (owner ruling R28). That ceramic stays in its owner's Imperial Kiln through Cleanup and the next Start of Round (`loadedInRound` is the round it was loaded) and is fired in the next round's firing, with that round's Kiln Die; meanwhile no Glaze & Load may load into that Imperial Kiln (R5). In Round 5 it is never fired and scores nothing; the computer players never spend the token there.
- Magistrate's Hall: both workers pay 4 Coins and advance 1 step (change 33); the Shifu's command may name 1 face-up Crown Order (`crownOrder`), optional (R21), reserved after the step; its position refills at the end of the turn with any other face-up reservation of the turn (L405).
- Reworking Table with Imperial Priority is allowed (P1); Glaze & Load placement legality uses current Shapes only (P3).

## Firing Phase

1. Nothing loaded: the firing is skipped and no Fire card is revealed.
2. Contributions: players with a Shared Kiln ceramic seal one card each, in any order, from the cards they hold (`PlayerState.contributionCards`, public): Bank, Tend and Stoke, plus Fuel Ledger Bank (1 Wood, −2) and Fuel Ledger Stoke (1 Wood, +2) for the Fuel Ledger owner, whose plain Bank and Stoke cost no Wood (change 26). `SUBMIT_CONTRIBUTION` names the card only; the former `fuelLedger` commitment is refused, and `private.private_submissions.use_fuel_ledger` is history. With no participant the window is skipped (INT).
3. On the last submission the server revalidates every sealed choice, pays, reveals all cards together and sets Base Heat = clamp(Kiln Die + Contributions, 0, 5).
4. Test Pieces (private peek, public bury; after Base Heat, before the Fire card), then the Fire card is revealed automatically and Actual Heat calculated, with Kiln Master's marker where one was placed at loading. There is no Heat-marker step (changes 28, 31). When the Fire deck runs out, or holds only buried cards, the open discard is shuffled and placed above the buried cards (R15).
5. Jun, Quality (Protective Saggars' ceramics are never Flawed), then after-Quality abilities (Protective Saggars' Standard → Fine, Second Firing, Ge) in each owner's chosen order with eligibility rechecked after each use. Ge crackles any 1 of its owner's ceramics from this firing, of any Quality (change 39): a Standard one becomes Fine, a Masterpiece, Fine or Flawed one keeps its Quality (`FinishedQuality.crackle` is independent of the Quality). Saggars' step and then Crackle may apply to one ceramic; a crackled ceramic keeps its marker through a Second Firing recalculation, which may target a crackled Flawed ceramic (owner ruling R30). Second Firing reveals 2 public cards; `SECOND_FIRING_CHOOSE` takes one, with an unused Jun (rev. 5 L646), in one command. The firing then finishes; there is no salvage step (change 30).
6. No free action is taken during the firing (rev. 5 L176): a ceramic of this firing that is Flawed after Quality may be sold only once Finished, in its owner's Order Phase turn or a later free-action window (owner ruling R26, which withdraws the after-Quality and Cleanup sale windows of owner ruling R20).

## Orders, Cleanup and scoring

- The Order Phase is a single pass in First Player order of free-action turns (rev. 5 L143, L318), the first chance to deliver the ceramics fired this round; a held Order may also be completed in its holder's Work turn (change 36). A player's Order Phase turn opens only when they have a completable held Order, a Finished Flawed ceramic or a usable Imperial Priority, and is skipped automatically otherwise (owner ruling R28); it closes by itself once nothing is left, and `END_ORDER_TURN` ends it at any time. Crackle declarations are either omitted (the engine searches and records the first that works) or given and used exactly. S07's "Carved, Impressed or Painted" is a Decoration alternative that a Crackle wildcard can fill. Each Crackle ceramic delivered scores 1 VP when the Order is completed (`CompletedOrderRecord.crackleVp`, Kiln Tradition VP; change 29); it counts for no tie-breaker.
- Cleanup returns workers and Setter's Marks; players over their hand limit discard in any order (a `parallel` window), a Main Order face down to the discard and a Starting Order to the box. Cleanup is no free-action window, so nothing is sold while trimming (owner ruling R26). The trim is skipped in Round 5 (INT).
- Exhibition is automatic (INT). Advanced Techs score no VP (change 27, which supersedes owner amendment A1): the score ledger, `TECH_ACQUIRED`, the score preview and the final breakdown have no Tech line. Connoisseur's Cabinet keeps its end-game VP. Final scoring and tie-breakers are computed by the server.

## Multiplayer

- **Routing.** Clients and the service decide who acts from `decisionPrompt(state)` only: `single`, `parallel` (`cleanup_hand_limit`) or `simultaneous_secret` (`firing_contributions`). A computer seat is advanced whenever it is among the actors, in every mode.
- **Revisions.** Commands normally name the current revision. In a `parallel` window a command based on any revision since the window opened is validated against the current head while its actor is pending, and a commit conflict is retried up to 3 times. Contributions are compare-and-swap on the head and the window.
- **Untrusted input.** `parseCommand` shape-checks every command before the service branches on it; the retired commands (V1.6.1's `COMMISSION_RESERVE`, `COMMISSION_CHOOSE_LOOKED`, `COMMISSION_GAIN`, `COMMISSION_STOP`, `USE_CANAL_BARGE`; revision 2's `COMMISSION_CHOOSE`, `COLOUR_SAMPLES_CHOOSE`, `COLOUR_SAMPLES_SWAP_CHOOSE`; a `SUBMIT_CONTRIBUTION` with `fuelLedger`; revision 3's `RESOLVE_HEAT_MARKERS` and `SALVAGE_FLAWED`, a Glaze & Load `heatMarkerCeramicId`, and a `SELECT_KILN` without `mainOrder`) are `MALFORMED_ACTION`.
- **Private delivery.** Responses carry the public projection and public events; the acting seat also receives its own `PrivatePlayerView` and its own event secrets. Reconnect rebuilds the private view from the head and the stored submissions and returns the seat's private event log. The game start persists `createGame`'s events, so the event count equals `eventSequence`. Public by design: the Setup Main Order take, the Magistrate's Hall Shifu's Crown Order, Kiln Master's marker, every sale and every completion with its window (a Work-turn completion reveals the Order then, rev. 5 L424); private: hands, looks and which looked cards were discarded. Whether an after-action window opens is computed from public facts only (owner ruling R27); whether an Order Phase turn opens may reflect a completable hidden Order (the accepted precedent, DESIGN §4.5; owner ruling R28).
- **Computer players.** A policy sees only its seat's `ActorView`. Its proposal is shape-checked and validated; on failure the service falls back to the canonical legal commands. A policy's exception is logged server-side, never returned: the response says only "<name> could not choose an action." The stored response of a computer command carries no private view. Labels are `rules-v1.6.2-<name>-<nnn>`.
- **Storage.** The in-memory store mirrors the Supabase RPCs and can apply `jsonb` key order on every read and write; a full seeded game ends in the same state hash either way.
- **Database.** `202610150001_v161_rules.sql` (written for V1.6.1 and edited in place for V1.6.2 before any deployment) rewrites every V1.4 gate (`server_create_room`, `server_join_room`, `server_add_computer_seat`, `server_commit_start`, `server_commit_transition`), allows `'1.6.2'`, schema 9 and `^r32-` fingerprints (owner revision 4), restricts new private submissions to the 5 Contribution cards and refuses a payload carrying `fuelLedger` (owner revision 3), persists the game start's events, refuses public rows carrying `hidden` or `secret`, and adds the seat-checked `server_list_private_events`. The owner reported it deployed with both Edge Functions on 2026-10-24 (ONLINE_GAME_SPEC "Transition status"), so it and `202610150002_playtest_v161.sql` are never edited again. For owner revision 5, `202610300001_v162_rev5_rules.sql` re-creates the five gates verbatim with only `^r33-` and schema 10, and lets `rooms_v162_fingerprint_check` accept `^r3[23]-…`, so the existing `r32-` rooms stay valid rows while every write path requires `r33-` (not yet deployed). Older rows stay as history.
